# Architecture Decision Records (ADR)

Architecture Decision Records (ADRs) capture important architectural decisions made throughout the lifetime of Cyros Labs.

An ADR exists to explain:

- Why a decision was made.
- What alternatives were considered.
- What trade-offs were accepted.
- What consequences the decision has.

Technology changes.

Architecture evolves.

The reasoning behind a decision should never be lost.

---

## Naming Convention

ADRs follow the format:

0001-record-architecture-decisions.md

0002-monorepo.md

0003-platform-first.md

...

Numbers are chronological and never reused.

---

## ADR Template

Each ADR should contain:

- Title
- Status
- Context
- Decision
- Consequences
- Alternatives Considered

---

## Status

Possible statuses include:

- Proposed
- Accepted
- Deprecated
- Superseded

---

## Guiding Principle

Every significant architectural decision deserves an ADR.

If a future engineer asks:

> "Why was this built this way?"

The answer should exist here.
